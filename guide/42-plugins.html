플러그인

플러그인은 자바스크립트로 짠 작은 확장입니다. 현재 문서를 읽고 고치는 일을 실행 한 번으로 되풀이합니다. AI 와 달리 결과가 늘 같고, 돈이 들지 않으며, 문서를 밖으로 보내지 않습니다. 여러 문서에 같은 정리를 할 때 알맞습니다.

플러그인은 .js 파일 하나입니다. 플러그인 폴더에 파일을 넣으면 바로 목록에 나타납니다. 따로 등록하지 않습니다. 앱과 함께 기본 플러그인 33개가 설치되고(아래 기본 플러그인 절), 직접 만들거나(새 플러그인 만들기 절) 다른 사람이 보낸 .lumiplugin 파일로 설치할 수 있습니다(설치와 내보내기 절).

플러그인 매니저

왼쪽 사이드바에서 AI 채팅 아래의 플러그인 버튼을 클릭하면 오른쪽에 플러그인 매니저가 열립니다.

  • 위 도구 모음: 검색란(플러그인 찾기), 새로 만들기, AI로 만들기, 플러그인 설치(.lumiplugin)..., 내 플러그인 폴더 열기.
  • 목록: 그룹별로 묶여 있습니다(아래 목록과 그룹 절).
  • 가운데 도구 모음: 선택한 플러그인을 실행, 코드 편집..., 복사본 만들기, 내보내기..., 비밀값... 넣기, 폴더 열기, 삭제합니다.
  • 아래: 선택한 플러그인의 설명, 할 수 있는 일(권한 배지), 접속할 곳, 실행하는 법, 최근 실행 결과입니다.

목록과 그룹

  • 내 플러그인이 든 그룹이 맨 위에 오고, 그 아래에 기본 플러그인 그룹이 정리·서식 → 구조 → 변환 → 점검 → 만들기 → 통계·모으기 → 일괄 차례로, 그 밖의 그룹 다음 맨 끝에 예제가 옵니다. 그룹이 없는 플러그인은 맨 위에 있습니다.
  • 처음 열면 기본 플러그인만 든 그룹은 접혀 있습니다(그룹 이름과 개수만 보입니다). 그룹 이름을 클릭하면 접고 펼칩니다. 검색란에 글자를 넣으면 찾은 플러그인이 든 그룹은 모두 펼쳐집니다.
  • 줄을 오른쪽 클릭하면 실행·코드 편집·이름 바꾸기·복사본 만들기·내보내기·그룹 옮기기·폴더 열기·삭제와 모두 접기·모두 펼치기가 나옵니다. 그룹 이름을 오른쪽 클릭하면 그룹 이름을 바꾸거나 그룹을 해제합니다. 줄에 마우스를 올리면 오른쪽에 삭제 버튼이 보입니다.
  • .lumiplugin 파일을 매니저나 앱 창에 끌어 놓으면 설치 확인 상자가 뜹니다.

권한 배지

플러그인이 할 수 있는 일은 이름 아래 배지로 보입니다. 주의할 권한은 경고 색입니다.

배지 뜻 머리 주석
문서 읽기 문서 텍스트·목록을 읽습니다 text.read · document.read
문서 수정 문서 텍스트를 고칩니다 text.write
문서 만들기·저장 새 문서를 열거나 문서를 저장합니다 document.write
앱 구성 읽기 앱의 명령·메뉴·작업 폴더 목록을 읽습니다 app.read
앱 명령 실행 (경고) 메뉴 명령을 실행합니다 app.commands
상태 표시줄 상태 표시줄에 칸 하나를 겁니다 ui.status
설정 기억 실행 사이에 작은 값을 기억합니다(sc.storage) storage
작업 폴더 파일 읽기 탭을 열지 않고 작업 폴더의 파일을 읽습니다 workspace.read
작업 폴더 파일 수정 (경고) 작업 폴더의 파일을 고쳐 씁니다 workspace.write
인터넷 접속 (경고) 정해진 사이트에 접속합니다 @network
비밀값 사용 (경고) 토큰 같은 비밀값을 씁니다 @secret
자동 실행(문서 저장·열기·닫기) (경고) 이벤트가 일어나면 묻지 않고 실행됩니다 @event

설정 기억은 따로 적지 않아도 코드에 sc.storage 가 있으면 배지가 붙습니다(숨은 기억이 없게).

기본 플러그인과 내 플러그인

기본 플러그인과 직접 만든 플러그인은 목록에서 똑같이 다룹니다.

  • 기본 플러그인을 코드 편집으로 고치거나 이름을 바꾸면 내 플러그인 폴더에 사본이 생기고 그 사본을 고칩니다. 목록에는 사본만 보입니다. 원래 파일은 그대로라 앱을 업데이트해도 고친 내용이 남습니다.
  • 삭제하면 기본 플러그인은 목록에서 숨기기만 합니다(목록 우클릭 메뉴의 숨긴 기본 플러그인 다시 보이기로 되살립니다). 고친 사본을 삭제하면 사본만 휴지통으로 가고 원래 플러그인이 다시 보입니다. 직접 만든 플러그인은 휴지통으로 갑니다. 플러그인을 지우면 그 플러그인이 기억해 둔 값(sc.storage)도 함께 지웁니다.

실행하기

  • 플러그인 매니저에서 선택하고 실행을 클릭합니다.
  • 명령 팔레트(Ctrl+K)에 플러그인: 을 입력하면 모든 플러그인이 나옵니다.
  • 플러그인마다 단축키를 줄 수 있습니다. 설정의 단축키 페이지에서 플러그인 슬롯 1 … 플러그인 슬롯 64(명령 ID script.run_0 … script.run_63)에 키를 지정합니다. 칸 번호는 플러그인을 추가하거나 지워도 그 플러그인을 따라갑니다.
  • 입력할 값이 있는 플러그인은 실행 전에 입력 창이 뜹니다.

실행 시간은 60초(자바스크립트 실행 기준)로 묶여 있고, 실행 중에는 중지로 멈춥니다.

결과는 어디에 나오나

결과는 종류마다 알맞은 곳에 나옵니다.

결과 나오는 곳 예
문서를 고쳤다 문서에 바로 들어가고, 알림 「표 정렬: 3곳을 고쳤습니다」와 [되돌리기] 버튼이 뜹니다. 바꿀 것이 없으면 「바꿀 곳이 없습니다」 정리·서식·구조·변환 플러그인
문제를 찾았다(점검) 아래 도구 창의 점검 결과 탭에 플러그인 이름으로 묶여 모이고, 알림 「그림 점검: 문제 4개」가 뜹니다. 없으면 「문제가 없습니다」 문서 구조 점검·그림 점검·문서 안 링크 점검·외부 링크 검사·파일 이름 규칙 점검·자주 틀리는 표현(보고)
보고서·새 문서 새 탭(저장하지 않은 문서, 제목 = 플러그인 이름 — 대상)으로 열리고, 알림 「문서 통계: 결과를 새 탭으로 열었습니다」 문서 통계·폴더 통계·할 일 모으기·회의록 …
  • 바뀐 문서마다 편집 한 번이므로 [되돌리기] 대신 그 문서에서 실행 취소(Ctrl+Z) 한 번으로도 되돌립니다. [되돌리기]는 그 뒤에 내가 다시 고친 문서는 건드리지 않습니다. 작업 폴더 파일에 직접 쓴 것(sc.workspace.write)은 되돌리지 못합니다.
  • 커서가 표 밖이거나 선택이 없는 것처럼 지금은 쓸 수 없는 상황은 오류(빨강)가 아니라 안내 알림(파란 i)으로 나옵니다. 메시지 창에도 보통 줄이고, 문서는 그대로입니다. [되돌리기] 알림은 일반 알림보다 오래(12초) 떠 있습니다.
  • 점검 결과 탭: 줄을 누르면 그 파일·줄로 가고(초점은 목록), 두 번 누르거나 Enter 를 누르면 편집기로 갑니다. 저장하지 않은 문서도 찾아가고, 문서가 아닌 파일(그림 등)은 파일 관리자에서 보입니다. 같은 플러그인을 다시 실행하면 그 플러그인 묶음만 바뀝니다. 묶음 머리를 누르면 접히고, 오른쪽 클릭 메뉴로 복사·「이 플러그인 결과 지우기」·「모두 지우기」를 합니다.
  • 메시지 탭은 기록용입니다: 실행 줄(시작·끝·걸린 시간·결과 요약 「3곳을 고쳤습니다 · 문제 4개」), 플러그인이 console.log 로 적은 텍스트와 오류가 쌓입니다. 플러그인이 돌려준 값은 메시지에 찍지 않습니다(AI 에이전트가 부르면 그대로 받습니다).

내 플러그인이 같은 방식으로 결과를 보이려면:

  • 고치는 플러그인은 고친 곳 수를 { changed: 3 } 처럼 돌려줍니다(알림 「3곳을 고쳤습니다」). 없으면 「문서를 고쳤습니다」.
  • 점검 플러그인은 찾은 것을 sc.findings.add([{ line, col, message, severity }]) 로 냅니다. 문제가 없을 때도 sc.findings.add([]) 를 불러 주면 지난 결과가 지워지고 「문제가 없습니다」가 뜹니다. 위치를 비우면 지금 문서, file(절대 경로)을 주면 그 파일입니다.
  • 보고서 플러그인은 sc.invoke('document.new', { title: '이름 — 대상', text }) 로 새 탭을 엽니다.

실행 확인과 지문

직접 만들었거나 고친 플러그인, 설치한 플러그인은 처음 실행할 때 플러그인 실행 확인 창이 뜹니다. 창에는 이름·폴더·권한·접속할 곳·비밀값·지문(파일 내용으로 만든 SHA-256 값의 앞 16자리)이 나오고, 앱 명령 실행·작업 폴더 파일 수정· 자동 실행 이벤트가 있으면 그 줄이 더 붙습니다. 처음 초점은 [취소]입니다.

  • [확인]을 클릭하면 그 지문을 허용한 것으로 기억하고 실행합니다. 다음부터는 묻지 않습니다.
  • 파일이 바뀌면 지문이 달라져 다시 묻습니다(「허용한 뒤 바뀌었습니다」). 앱 밖에서 고쳤거나, 같은 ID 를 다시 설치해 덮어쓴 경우입니다.
  • 앱의 편집 탭에서 저장한 내 플러그인과 새 플러그인 만들기로 만든 플러그인은 이 앱에서 쓴 것이므로 다시 묻지 않습니다.
  • 앱과 함께 설치된 기본 플러그인은 묻지 않습니다.

새 플러그인 만들기

매니저의 새로 만들기를 클릭하면 새 플러그인 창이 뜹니다. 여기서 정한 값이 플러그인 맨 위의 머리 주석이 됩니다. 창 아래 미리보기에 값을 바꿀 때마다 만들어질 머리 주석이 보입니다.

칸 내용
이름 목록에 보일 이름(필수). 비어 있으면 [만들기]가 흐립니다
ID 영문 소문자·숫자·-. 이름에서 제안하며(한글 이름은 직접 적습니다) 파일 이름이 됩니다(<ID>.js). 이미 있는 ID(기본 플러그인 포함)·같은 이름의 파일·Windows 예약 이름은 아래에 오류 줄이 나옵니다
한 줄 설명 이 플러그인이 하는 일. 비우면 시작 템플릿의 기본 설명. 설명은 기본 플러그인과 같은 양식(한 줄 + 사용법 + 한계)으로 만들어집니다
그룹 「내 플러그인」(기본), 내 그룹, 기본 플러그인 그룹, 새 그룹...(옆에 이름 칸이 생깁니다)
버전 · 만든 사람 버전은 1.0.0 처럼 숫자와 점. 만든 사람은 마지막에 적은 값을 기억합니다
시작 템플릿 본문의 출발점(아래 표). 고르면 권한 기본값이 바뀝니다
할 수 있는 일 권한 체크 상자 10개(매니저 배지와 같은 이름)와 인터넷 접속(체크하면 접속할 곳 칸이 생깁니다)
자동 실행 문서를 저장한 뒤 · 파일을 연 뒤 · 파일 탭을 닫은 뒤(기본은 모두 꺼짐)
저장 위치 내 플러그인 폴더/<ID>.js. [폴더 열기]로 폴더를 엽니다

시작 템플릿은 실제로 도는 짧은 본문입니다. 주석과 메시지는 화면 언어로 들어갑니다.

시작 템플릿 본문 기본 권한
선택한 텍스트 바꾸기 선택한 텍스트를 읽어 바꾼 뒤 그 자리에 넣습니다(예제: 영문 대문자로) 텍스트 읽기, 텍스트 수정
문서 전체 바꾸기 문서 전체를 읽어 코드 블록 밖을 정리합니다(예제: 겹친 빈 줄 줄이기) 텍스트 읽기, 텍스트 수정
보고서 만들기(새 문서로) 지금 문서를 읽어 보고서를 새 문서로 만듭니다(예제: 줄·글자 수와 제목 목록) 텍스트 읽기, 새 문서·저장
작업 폴더 점검 작업 폴더의 마크다운 파일을 탭으로 열지 않고 읽어 점검 결과를 새 문서로 만듭니다 작업 폴더 파일 읽기, 새 문서·저장
빈 틀 자주 쓰는 기능을 주석으로 적어 둔 빈 본문입니다 없음(적지 않으면 텍스트 읽기·수정)
  • 주의할 권한(앱 명령 실행·작업 폴더 파일 수정·인터넷 접속)을 체크하면 경고 줄이 나옵니다. 시작 템플릿이 쓰는 권한을 빼도 경고 줄이 나옵니다 (그대로 만들면 그 기능을 부를 때 오류로 멈춥니다).
  • 자동 실행을 체크하면 「이벤트로 돌면 묻지 않고 실행됩니다」가 나옵니다.
  • 만들기(Enter)는 파일을 만들고, 매니저에서 그 플러그인을 고르고, 코드를 편집 탭으로 엽니다. 같은 이름의 파일이 그 사이에 생겼으면 덮지 않습니다.
  • AI로 만들기(창 왼쪽 아래)는 이 입력(이름·ID·설명·시작 템플릿·문서 권한·접속할 곳)을 AI 채팅 입력란에 채워 넘깁니다. 보내기는 직접 합니다.

코드 편집

**코드 편집...**은 선택한 플러그인을 편집 탭으로 엽니다. 플러그인 코드는 문서와 같은 탭 영역에서 고칩니다. 편집기 위 도구 모음에 버튼 세 개가 있습니다.

  • 저장(Ctrl+S): 여기서 저장한 내 플러그인은 실행 확인을 다시 묻지 않습니다.
  • 실행(F5): 저장한 뒤 마지막으로 보던 문서에 실행합니다. 결과가 그 문서에 바로 들어가니, 연습할 때는 버려도 되는 문서를 열어 두세요.
  • 플러그인 정보: 이름·그룹·권한·접속할 곳·입력값을 양식으로 고칩니다(아래 「헤더 주석」).

입력하면 자동 완성이 뜹니다. sc. 뒤에는 쓸 수 있는 함수, sc.invoke(' 안에서는 앱 기능 이름과 그 기능에 필요한 권한이 나옵니다. 이름 위에 마우스를 올리면 설명이 보이고, 구문 오류는 밑줄로 표시됩니다.

AI 로 만들기

  1. 매니저의 AI로 만들기를 클릭하거나, AI 채팅 입력란에 /플러그인(또는 /script)을 입력합니다. /플러그인 선택한 줄의 앞뒤 공백 지우기 처럼 한 줄로 써도 됩니다.
  2. 하고 싶은 일을 써서 보냅니다. 문서 내용은 보내지 않고 요청 내용만 보냅니다.
  3. AI 가 코드를 만들면 앱이 형식과 구문을 검사합니다. 걸리면 AI 에게 한 번 더 고쳐 달라고 합니다.
  4. 답 아래의 미리보기·저장을 클릭하면 코드 전체와 요청한 권한을 보여 줍니다. 문서 읽기·쓰기 밖의 권한(인터넷 접속, 비밀값, 새 문서 만들기)은 경고 색으로 따로 나옵니다.
  5. 저장을 클릭하면 내 플러그인 폴더에 저장합니다. 저장만 하고 실행하지 않습니다. 처음 실행할 때 실행 확인을 거칩니다.

AI 설정이 없으면 설정 대화상자의 AI 페이지가 열립니다.

설치와 내보내기(.lumiplugin)

플러그인을 다른 사람에게 줄 때는 .lumiplugin 파일 하나로 묶어 보냅니다(메일·메신저로 주고받기 쉽습니다). 안에는 플러그인 파일과 정보 파일(ID·이름·버전·만든 이·파일 목록·지문)이 들어 있습니다.

내보내기

  1. 매니저에서 플러그인을 고르고 가운데 도구 모음(또는 줄 우클릭 메뉴)의 **내보내기...**를 클릭합니다.
  2. 저장 창에서 위치를 고릅니다. 기본 이름은 <ID>-<버전>.lumiplugin 입니다.

파일 하나짜리 플러그인은 .js 와 같은 이름의 보조 파일(.md·.txt·.json·.csv·.tsv)만 함께 묶습니다. 비밀값(@secret 의 값)과 기억해 둔 값(sc.storage)은 묶지 않습니다.

설치

다음 어느 길로든 설치 확인 상자가 뜹니다.

  • 매니저 위 도구 모음의 플러그인 설치(.lumiplugin)... → 열기 창에서 파일 고르기
  • 명령 팔레트의 플러그인 설치...
  • .lumiplugin 파일을 앱 창이나 매니저에 끌어 놓기, 앱의 탐색기에서 두 번 클릭
  • Windows 탐색기에서 .lumiplugin 파일을 두 번 클릭(MDStudio 로 열도록 연결했을 때 — 아래 「파일 연결」)

설치 확인 상자에는 다음이 보입니다.

  • 지시문 「'이름' 버전을(를) 설치할까요?」, 만든 이, ID
  • 할 수 있는 일(권한 배지와 같은 이름), 접속할 곳, 비밀값, 자동 실행 이벤트
  • 같은 ID 가 이미 있으면 버전 견주기 — 새 버전으로 바꿈 / 같은 버전(덮어씀) / 낮은 버전(예전 버전으로 돌아감)
  • 같은 ID 의 기본 플러그인을 가리게 되면 그 안내(지우면 기본 플러그인이 다시 보입니다)
  • 자세히 보기를 펼치면 코드 앞부분(80줄)
  • 아래 줄: 「설치한 플러그인은 처음 실행할 때 할 수 있는 일을 다시 확인받습니다.」

기본 버튼은 설치(덮어쓸 때는 덮어쓰기)입니다. 다만 자동 실행 이벤트·앱 명령 실행·작업 폴더 파일 수정·모든 사이트 접속·비밀값을 가진 플러그인은 아이콘이 경고로 바뀌고 취소가 기본 버튼입니다(Enter 한 번으로 들이지 않게).

파일 연결(Windows)

.lumiplugin 파일을 MDStudio 로 열도록 연결해 두면, Windows 탐색기에서 두 번 클릭할 때 MDStudio 가 열리고 설치 확인 상자가 뜹니다. 앱이 이미 떠 있으면 떠 있는 창에서 확인 상자가 뜹니다. 파일은 문서 탭으로 열리지 않습니다.

  • 연결하는 법: Windows 탐색기에서 .lumiplugin 파일을 오른쪽 클릭 > 연결 프로그램 > 다른 앱 선택에서 MDStudio 를 고릅니다.
  • Microsoft Store 밖 배포판에는 설정 > 문서 > 파일 연결이 있습니다: .lumiplugin (플러그인 설치)를 체크하고 [적용]을 클릭합니다(현재 사용자 설정에만 쓰고 「연결 프로그램」 목록에 올리기만 합니다). 그 판의 「시작할 때 파일 연결 여부 묻기」는 문서 형식만 묻습니다.

안전 규칙

  • 설치는 신뢰를 주지 않습니다. 정보 파일의 지문은 파일이 깨지지 않았는지 보는 값이지 만든 사람의 서명이 아닙니다. 설치한 플러그인도 처음 실행할 때 실행 확인을 받고, 덮어쓰면 지문이 바뀌어 다시 묻습니다.
  • 파일 연결·끌어 놓기로 들어온 파일도 확인 상자 없이 설치하지 않고, 실행을 허락하지도 않습니다. 자동 실행 이벤트가 있는 플러그인도 허용하기 전에는 돌지 않습니다.
  • 풀기 전에 묶음을 검사합니다: 파일 크기 8MB, 항목 64개, 항목 하나 2MB·합계 4MB, 상대 경로만(..·절대 경로 거절), 링크 항목 거절, 허용 확장자(.js·.json·.md·.txt·.csv·.tsv), 파일 목록·지문 일치, 머리 주석의 ID 와 정보 파일의 ID 일치. 하나라도 어긋나면 아무것도 풀지 않고 오류 상자를 띄웁니다.

예제 문서로 시험해 보기

기본 플러그인 33개를 직접 돌려 볼 수 있는 예제 문서 묶음이 앱에 들어 있습니다. 플러그인 매니저 위 도구 줄의 [예제 문서] 버튼를 누르면 묶음이 설정 폴더의 plugin-samples/<언어> 로 복사되고, 그 폴더가 탐색기에 열리며 README.md 가 열립니다. README 의 표에 플러그인마다 어느 문서를 열어 무엇을 해 보면 되는지, 기대 결과가 어떤지 적혀 있습니다. 문서는 일부러 어지럽혀 두었으니 마음껏 고쳐도 됩니다. 앱에 든 원본은 읽기 전용이라 그대로입니다.

이미 복사해 둔 예제가 있으면 덮어쓰지 않고 묻습니다. [예]는 묶음의 파일을 처음 상태로 다시 받고(직접 더한 파일은 그대로 둡니다), [아니요]는 지금 있는 것을 그대로 엽니다. 「외부 링크 검사」와 「웹 문서 스크랩」은 인터넷에 접속하며 시험용 주소(example.com)만 씁니다.

헤더 주석

플러그인의 이름·그룹·권한 같은 정보는 따로 파일을 두지 않고 스크립트 맨 위의 주석에 적습니다. 직접 고쳐도 되고, 편집 탭의 플러그인 정보 버튼으로 양식에서 고쳐도 됩니다.

/**
 * @name 웹 문서 스크랩
 * @group 가져오기
 * @permissions document.read text.write
 * @network *
 * @param {uri} url 주소
 * @param {integer:1..6} [heading=2] 제목 단계
 * @description
 * 웹 페이지의 본문을 마크다운으로 바꿔 커서 자리에 넣습니다.
 */

sc.operation('run', async ({ url, heading }) => {
  // …
});
태그 뜻
@name 목록에 보일 이름(없으면 파일 이름)
@group 매니저에서 묶일 그룹(없으면 그룹 없이 목록 맨 위에)
@version · @author 버전과 만든 사람
@description 설명. 다음 줄부터 여러 줄로 쓰며 마크다운을 쓸 수 있습니다
@permissions 쓸 기능의 범주(아래 sc API 참고 절). 적지 않으면 텍스트 읽기·수정
@network 접속할 사이트를 공백으로 나눠 적습니다. * 는 모든 사이트, 적지 않으면 접속하지 않습니다
@secret 이름 제목 토큰 같은 비밀값. 값은 매니저의 **비밀값...**에서 넣고 OS 키 저장소에 보관합니다
@param {형} 이름 제목 — 설명 실행 전에 물을 입력값. [이름=기본값] 은 선택 입력입니다. 형은 string·integer·boolean·uri·`enum:a
@event 이벤트 이벤트가 일어나면 자동으로 실행합니다(document.saved·document.opened·document.closed, 아래 이벤트로 자동 실행하기 절)
@mcp on · @agent 설명 AI 에이전트가 이 플러그인을 호출할 수 있게 하고, 에이전트에게 보일 설명을 적습니다

플러그인은 앱 설정 폴더나 다른 프로그램의 설정 폴더에 있는 파일을 열거나 저장할 수 없습니다.

폴더 구조

plugins/
  tidy-lines.js   ← 플러그인 하나 = 파일 하나(머리 주석 + sc.operation('run', …))
  my-tool.js
  _types/
    sc.d.ts       ← 바깥 편집기용 선언 파일(앱이 씁니다, 목록에는 나오지 않음)

sc API 참고

sc.invoke(이름, 인자) 로 앱 기능을 호출합니다. 헤더 주석의 @permissions 에 범주를 적어야 합니다(범주가 「없음」이면 누구나 씁니다). 아래 이름은 편집기 자동 완성(sc.invoke(')과 선언 파일 sc.d.ts 의 ScOp 와 같습니다.

앱과 연결하기

플러그인은 문서뿐 아니라 앱 자체도 다룹니다. 아래 기능도 sc.invoke 로 호출하고, 짧게 쓰는 함수가 함께 있습니다.

이름 범주 짧은 꼴 하는 일
app.describe app.read sc.app.describe(부분?) 앱 구성을 돌려줍니다. app(이름·버전·API 버전·언어·테마), commands(명령 ID·이름·켜짐·체크·단축키·메뉴), menus, workspace(작업 폴더), events
app.command.run app.commands sc.app.run(명령 ID) 앱 명령을 실행합니다
app.locale (없음) sc.app.locale() 화면 언어 코드(ko·en …). 플러그인이 만드는 글·알림을 앱 언어로 쓸 때
ui.status.set ui.status sc.status.set(텍스트, 툴팁?) · sc.status.clear() 상태 표시줄에 이 플러그인의 칸을 겁니다(플러그인마다 하나, 60자까지)
ui.notify (없음) sc.notify(텍스트, 수준?) 알림을 띄웁니다(info·success·warning·error, 한 번 실행에 5개까지)
ui.findings.add (없음) sc.findings.add(항목 | 항목[]) 점검 결과를 냅니다. 항목 = { message, severity?, file?, doc?, line?, col? }(심각도 error·warning(기본)·info, 줄·칸 1부터). 끝나면 점검 결과 탭에 이 플러그인 이름으로 묶여 보이고, 다시 실행하면 그 묶음만 바뀝니다. 빈 배열 = 「문제 없음」. 한 번 실행에 1,000개까지
  • 플러그인은 실행 전에 뜬 사본을 읽습니다. 명령 실행·상태 칸·알림은 요청으로 적어 두었다가, 플러그인이 끝나고 문서 편집과 저장이 들어간 뒤에 차례대로 일어납니다. 실패하거나 중지한 실행의 요청은 버립니다.
  • 실행할 수 있는 명령은 app.describe 의 commands 에 있는 것뿐입니다. 종료·설정·탐색기 파일 작업·플러그인 실행·단축키 설정 같은 명령은 목록에 없고 실행할 수 없습니다. 실행 시점에 꺼져 있는 명령은 건너뛰고 메시지 창에 적습니다.

설정 기억(sc.storage)

플러그인마다 실행 사이에 남는 작은 저장소가 있습니다. 다른 플러그인의 값은 읽을 수 없습니다. 범주 storage 는 누구나 쓸 수 있고, 코드에 sc.storage 가 있으면 매니저에 「설정 기억」 배지가 붙습니다.

이름 짧은 꼴 하는 일
storage.get sc.storage.get(키, 기본값?) 값을 읽습니다. 없으면 기본값
storage.set sc.storage.set(키, 값) 값을 적습니다(JSON 으로 바꿀 수 있는 값)
storage.delete sc.storage.delete(키) 키를 지웁니다
storage.keys sc.storage.keys() 적어 둔 키 목록
storage.clear sc.storage.clear() 저장소를 비웁니다
  • 실행 전에 저장된 값을 사본으로 읽고, 성공으로 끝난 실행만 바뀐 값을 씁니다(실패·중지한 실행의 변경은 버림).
  • 64KB·키 256개·키 이름 128자까지. 파일에 평문으로 남으므로 토큰 같은 비밀값은 넣지 않습니다(@secret 을 씁니다).
  • 플러그인을 지우면 그 플러그인의 값도 지웁니다.

작업 폴더 파일(sc.workspace)

탭을 열지 않고 파일을 읽고 고칩니다. 닿는 곳은 탐색기의 작업 폴더와 열린 문서들의 폴더뿐입니다(앱 설정·플러그인 폴더 같은 곳은 막힘, 심볼릭 링크·..·네트워크 경로 거절). 문서 확장자 파일만 다룹니다.

이름 범주 짧은 꼴 하는 일
workspace.files workspace.read sc.workspace.files({folder?, exts?, max?}) 파일 목록(기본 마크다운, 2,000개 — max 로 5,000개까지). .git·node_modules 는 건너뜁니다
workspace.read workspace.read sc.workspace.read(경로) 파일 내용(파일 하나 4MB, 한 실행 합계 64MB)
workspace.exists workspace.read sc.workspace.exists(경로들) 파일이 있는지(닿을 수 없는 곳은 null)
workspace.write workspace.write sc.workspace.write(경로, 텍스트) 이 실행에서 읽은 파일만 고쳐 씁니다(한 실행 500개)

workspace.write 는 바로 쓰지 않고 요청으로 적었다가 실행이 끝난 뒤 앱이 씁니다. 탭으로 열린 파일은 편집기에 편집 한 번으로 넣고 저장합니다 (고치는 중인 탭은 건너뜀). 열리지 않은 파일은 디스크에 쓰되, 읽은 뒤 바뀐 파일은 건너뛰고 BOM·줄 끝(CRLF)은 그대로 둡니다.

이벤트로 자동 실행하기

헤더 주석에 @event 이벤트 를 적으면 그 일이 일어난 뒤 플러그인이 실행됩니다. 동작은 { event, doc, title, path } 를 인자로 받습니다.

이벤트 언제
document.saved 사용자가 문서를 저장했을 때(자동 저장·플러그인·AI 에이전트가 한 저장은 제외)
document.opened 사용자가 파일을 열었을 때(지난 세션 복원·새 문서·플러그인 코드 탭·플러그인이나 AI 에이전트가 연 파일은 제외)
document.closed 파일이 있는 문서 탭을 닫았을 때(인자에 doc 없음, 플러그인·AI 에이전트가 닫은 것 제외)
  • 실행을 허락한 플러그인만 자동으로 돕니다. 실행 확인 창에 「다음 일이 일어나면 묻지 않고 실행합니다」가 따로 나옵니다.
  • 자동 실행은 시작·끝 알림 없이 돌고, 메시지 창에 기록합니다. 비밀값이 비어 있으면 건너뜁니다.
  • 이벤트가 부른 실행은 파일·탭 명령(열기·닫기·저장)을 요청해도 건너뜁니다(끝없이 서로 부르지 않게). 밀린 자동 실행이 32개를 넘으면 뒤의 것을 건너뜁니다.

선언 파일(sc.d.ts)

매니저를 열면 내 플러그인 폴더의 _types/sc.d.ts 에 TypeScript 선언 파일을 씁니다. 새 플러그인의 머리 주석 뒤에는 /// <reference path="./_types/sc.d.ts" /> 가 들어가 있어, VS Code 같은 바깥 편집기에서도 sc 의 자동 완성과 검사를 받을 수 있습니다. 기능 이름(ScOp)·권한(ScPermission)·이벤트(ScEvent)는 이 쪽의 표와 같습니다.

자주 묻는 것

플러그인이 목록에 안 보여요. 검색란이 비어 있는지 봅니다. 기본 플러그인 그룹은 처음에 접혀 있으니 그룹 이름을 클릭해 펼칩니다. 지운 기본 플러그인은 목록 우클릭 메뉴의 숨긴 기본 플러그인 다시 보이기로 되살립니다. 머리 주석을 읽지 못한 플러그인은 목록에 오류로 표시되니 **코드 편집...**으로 고칩니다. _ 로 시작하는 폴더(_types 등)는 목록에 들지 않습니다. 명령 팔레트에는 64개까지 나옵니다.

실행 확인에서 [취소]했어요(권한을 거절했다면?). 실행하지 않고 끝납니다. 허락은 기억하지 않으므로 다음에 실행하면 다시 묻습니다. 권한을 줄여서 쓰고 싶으면 플러그인 정보에서 권한을 빼고 저장합니다. 그 권한이 필요한 기능을 부르면 플러그인은 오류로 멈추고 메시지 창에 이유가 나옵니다.

이벤트로 도는 플러그인을 멈추고 싶어요. 머리 주석에서 @event 줄을 지우고 저장하거나, 매니저에서 그 플러그인을 삭제합니다. 앱 밖에서 파일이 바뀌면 지문이 달라져 다시 허락하기 전까지 자동 실행이 돌지 않습니다. 무엇이 언제 돌았는지는 메시지 창에 남습니다.

.lumiplugin 을 두 번 클릭해도 MDStudio 가 열리지 않아요. Windows 탐색기에서 .lumiplugin 파일을 오른쪽 클릭 > 연결 프로그램 > 다른 앱 선택에서 MDStudio 를 고릅니다(Microsoft Store 밖 배포판은 설정 > 문서 > 파일 연결에서도 됩니다). 연결하지 않아도 앱 창에 끌어 놓거나 매니저의 **플러그인 설치(.lumiplugin)...**로 설치할 수 있습니다.

설치했는데 실행하니 또 물어요. 정상입니다. 설치는 실행 허락을 주지 않습니다. 실행 확인에서 권한과 지문을 보고 허락합니다.
